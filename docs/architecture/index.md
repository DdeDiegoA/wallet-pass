# Architecture

> Project: wallet-pass | Stack: Node/TypeScript (pnpm + tsup + vitest) | Generated by protto on 2026-09-06.

## Overview
Librería que envuelve un QR ya emitido por el integrador y produce pases Apple Wallet (`.pkpass`, vía `passkit-generator`) + Google Wallet (JWT, vía `@googleapis/walletobjects`), con esquema unificado, ciclo de vida (create/update/expire/revoke) y capa de seguridad. Ver `PRD.md` §5 para el diagrama completo.

## Build & Test
- Build: `pnpm run build` (tsup)
- Test: `pnpm test` (vitest)
- Typecheck: `pnpm run typecheck`

## Structure
- `src/` — código de la librería (`index.ts` entrypoint)
- `docs/` — documentation
- `.claude/` / `.opencode/` — agent configuration

## Entrypoints
- `src/wallet-pass.ts` — entrypoint público principal. Exporta la clase `WalletPass`; su constructor recibe el esquema unificado del pase y expone `.apple()` para emitir `.pkpass` y `.google()` para emitir el JWT/link add-to-wallet.
- `src/index.ts` — re-export de `WalletPass` (compatibilidad con import por paquete).

## DSL WalletPass

```ts
import { WalletPass } from "wallet-pass";

const pass = new WalletPass({
  type: "event-ticket",
  qr: "cinemark|txn=4821|seat=F12|session=2026-09-12T21:30",
  meta: {
    eventName: "Dune: Parte Tres",
    venue: "Cinemark Centro",
    startsAt: new Date("2026-09-12T21:30:00-05:00"),
  },
  holder: { seat: "F12", door: "B" },
  branding: { logo: buffer, backgroundColor: "#000000" },
});

const applePkpass: Buffer = await pass.apple();
const google: { url: string; jwt: string } = await pass.google();
```

## Lifecycle (Fase 2)

- **Apple Web Service** (Apple llama al server del integrador, HTTPS + header `Authorization: ApplePass <authenticationToken>`): el integrador monta cinco endpoints — `POST /v1/devices/{deviceLibraryIdentifier}/registrations/{passTypeIdentifier}/{serialNumber}` (registerDevice), `DELETE .../registrations/.../{serialNumber}` (unregisterDevice), `GET /v1/devices/{deviceLibraryIdentifier}/registrations/{passTypeIdentifier}?passesUpdatedSince=` (getSerialsForDevice), `GET /v1/passes/{passTypeIdentifier}/{serialNumber}` (getLatestPass, devuelve el `.pkpass` actualizado o 304) y `POST /v1/log` (logErrors). Push APNs opcional para disparar refresh.
- **Storage inyectable**: los handlers operan contra una interfaz de storage que el consumidor implementa (registros device↔pass, serials, pass actual); la librería no asume DB.
- **Google REST**: cliente que hace upsert del `EventTicketObject` — `insert` si no existe, `patch` si existe — para update/expire/revoke (cambios de `state`, `validTimeInterval`); el integrador llama a Google, no al revés.

## Seguridad (Fase 3)

- **Gestión de claves**: credenciales por env var (default) o explícitas por-llamada en `.apple()`/`.google()` — permite rotación sin downtime y multi-tenant (un Pass Type ID / issuer por tenant) sin reiniciar el proceso.
- **PKCS#11/HSM real: fuera de alcance v1** (documentado, no implementado) — requiere infraestructura del integrador (KMS/HSM), no es responsabilidad de una librería OSS. Ver `docs/decisions.md` → `2026-09-07-seguridad-v1-scope`.
- **Validación tipada por passType**: antes de emitir se valida el esquema contra el tipo de pase (campos requeridos, formatos); la sanitización básica de strings ya vive en `src/sanitize.ts` desde Fase 1.
- **Audit log `onEmit`**: hook opcional que recibe solo metadata hasheada del pase (nunca el QR ni el serial crudo) para log de emisión sin PII.
